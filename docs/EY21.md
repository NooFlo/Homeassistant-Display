# Installing on the Kindle Paperwhite 11 (EY21, 2021)

This is the primary target device of this repository. The defaults in
`kindle/kiosk.env` and `kindle-ui/html/config.js` are set for it, so if
you have an EY21 you can follow this page end to end instead of piecing
together `INSTALL.md` and `MODELS.md`.

What changes vs the old-generation (PW1) flow: firmware 5.14+ does not
reliably run our upstart jobs, so the kiosk is started from **KUAL**
instead of at boot, and the panel is 300 ppi (all UI sizes doubled).

## 0. Before first connecting to WiFi

1. Check the firmware: Settings → Menu → Device Info. Note the exact
   version (5.14.x / 5.15.x) — the jailbreak is firmware-specific.
2. **Airplane mode on** until the jailbreak is done. If the firmware is
   already too new for the current exploit, you cannot downgrade — check
   the [KindleModding wiki](https://kindlemodding.org/) first to confirm
   your version is jailbreakable *before* letting it online.

## 1. Jailbreak + KUAL + USBNetwork

Follow the KindleModding wiki pages for your firmware. You need, in
order:

1. the jailbreak itself,
2. **MRPI** (Motorola RISK/Pre-Install framework) so package installs work,
3. **KUAL**,
4. **USBNetwork** — configure it for WiFi SSH (or use it over USB).

Verify SSH before going further:

```sh
ssh root@<kindle-ip>
# you should land in a root shell; then check the two device paths:
ls /dev/input/        # touch is expected on event0 on the EY21
ls /sys/class/rtc/    # wake RTC expected at rtc1
```

Confirm touch by tapping while this runs (it exits as soon as the
screen is touched):

```sh
timeout 3 dd if=/dev/input/event0 bs=64 count=1 >/dev/null && echo TOUCH-OK
```

And that the RTC accepts a wake alarm:

```sh
echo 0 > /sys/class/rtc/rtc1/wakealarm && echo RTC-OK
```

If touch is on a different `eventN` or the RTC is `rtc0`, edit
`kindle/kiosk.env` accordingly.

## 2. Server side (your Docker host on the same LAN)

```sh
cp .env.example .env
# set HA_URL and your Home Assistant long-lived access token
docker compose up -d
```

Check from a desktop browser:

- `http://<server-ip>:8124` → dashboard
- `http://<server-ip>:8124/api/states/sun.sun` → JSON (token proxy OK)

## 3. Home Assistant side

- Long-lived token in `.env` (`KINDLE_HA_TOKEN`).
- Merge `homeassistant/configuration-snippet.yaml` → `input_boolean.kindle_wake`.
- Merge `homeassistant/automation-presence-wake.yaml`, adapt the
  presence triggers, restart HA.

## 4. Kindle side (KUAL-only install)

Set `SERVER_IP` in `kindle/kiosk.env`, then:

```sh
KINDLE_IP=<kindle-ip> KUAL_ONLY=1 bash scripts/install-kindle.sh
```

This pushes everything to `/mnt/us` and **skips the upstart jobs** (they
are not used on this firmware). Nothing is written to the rootfs on the
EY21 — the whole kiosk lives on the userstore and is trivially removed.

Then, on the Kindle:

**KUAL → KindleKiosk → Start Kiosk**

That single entry does three things: suppresses the framework
screensaver, starts the sleep/wake engine (background), and opens the
dashboard in the stock browser.

## 5. Verify the power story

| Check | Expectation |
|---|---|
| Dashboard renders, clock ticks | Fills 1236×1648, no clipping; tap a light → inverts instantly, state follows |
| Leave it idle `IDLE` seconds | Padlock ASLEEP view; next idle cycle ends in deep sleep (WiFi off; ping stops) |
| Press power button while suspended | Wakes; the stock UI or dashboard reappears; Start Kiosk via KUAL if the browser didn't resume |
| Turn on `input_boolean.kindle_wake` in HA while idle | Dashboard reloads within ~`POLL` seconds, touch live |
| Check `sensor.kindle_battery` in HA | Battery percentage appears after the first awake cycle |

Battery note: on the PW5, verify what `gasgauge-info -s` prints in your
shell — if the percentage isn't a clean number, paste it in an issue and
the push parsing in `kindle/bin/kiosk-sleep.sh` gets adjusted.

## 6. Daily use on the EY21

- After a **reboot** the kiosk does not auto-start — open KUAL →
  KindleKiosk → Start Kiosk. (Auto-start hooks exist if you later want
  them via a framework extension, but manual start keeps the install
  rootfs-free.)
- **KUAL → KindleKiosk → Toggle Sleep Engine** to keep it awake while
  charging/debugging.
- **KUAL → KindleKiosk → Stop Kiosk** returns the stock reader UI.

## 7. Uninstall

```sh
ssh root@<kindle-ip>
rm -rf /mnt/us/kiosk /mnt/us/extensions/KindleKiosk
rm -f /mnt/us/DISABLE_KIOSK /mnt/us/DISABLE_SLEEP
```

Reboot, and the Kindle is back to stock behavior.

## EY21 fallbacks, if something misbehaves

- **`web-reader` app id doesn't open the browser** on your firmware:
  look for the browser binary under `/var/local/` and launch it with
  the URL as argument; the KUAL script is the single place to change.
- **Touch targets feel small**: the reference UI is already sized for
  300 ppi; a figcraft rebuild should use the doubled minimums from
  `docs/UI-DESIGN-PROMPT.md` (≥128 device px).
- **Ghosting bothers you**: the sleep view re-renders on every wake,
  which triggers a full refresh; for more aggressive cleaning, lower
  `LIGHT_SLEEP_MAX` so it deep-sleeps sooner.
