# Installing on the Kindle Paperwhite 11 (EY21, 2021)

This is the primary target device of this repository. The defaults in
`kindle/kiosk.env`, `kindle-ui/html/config.js` and `renderer/config.json`
are set for it, so if you have an EY21 you can follow this page end to end
instead of piecing together `INSTALL.md` and `MODELS.md`.

Two kiosk modes are available:

- **Browser kiosk** (web app in the stock browser, framework fully running):
  `KUAL -> KindleKiosk -> Start Kiosk`
- **Native kiosk** (framework-less loop, renders server-side PNGs via FBInk —
  see [NATIVE.md](NATIVE.md)): `KUAL -> KindleNative -> Start Native Kiosk`

On the EY21 the **native kiosk is the recommended mode** (the PW5's stock
browser adds nothing; the native loop has better refresh control and battery
life). Both are installed by the same script.

What changes vs the old-generation (PW1) flow: firmware 5.14+ does not
reliably run our upstart jobs, so both kiosks are started from **KUAL**
instead of at boot, and the panel is 300 ppi (all UI sizes doubled).

## 0. Before first connecting to WiFi

1. Check the firmware: Settings → Menu → Device Info. Note the exact
   version (5.14.x / 5.15.x) — the jailbreak is firmware-specific.
2. **Airplane mode on** until the jailbreak is done. If the firmware is
   already too new for the current exploit, you cannot downgrade — check
   the [KindleModding wiki](https://kindlemodding.org/) first to confirm
   your version is jailbreakable *before* letting it online.

## 1. Jailbreak + KUAL + USBNetwork + FBInk

Follow the KindleModding wiki pages for your firmware. You need, in
order:

1. the jailbreak itself,
2. **MRPI** so package installs work,
3. **KUAL**,
4. **USBNetwork** — configure it for WiFi SSH (or use it over USB),
5. **FBInk** for the native mode (KUAL extension or binary on the PATH;
   set `FBINK_BIN` in `kindle/kiosk.env` if it is not just `fbink`).

Verify SSH before going further:

```sh
ssh root@<kindle-ip>
# confirm the two device paths:
ls /dev/input/        # touch is expected on event0 on the EY21
ls /sys/class/rtc/    # wake RTC expected at rtc1
```

Confirm touch by tapping while this runs (it exits as soon as the
screen is touched):

```sh
timeout 3 dd if=/dev/input/event0 bs=64 count=1 >/dev/null && echo TOUCH-OK
```

And that the RTC accepts a wake alarm:

```sh
echo 0 > /sys/class/rtc/rtc1/wakealarm && echo RTC-OK
```

If touch is on a different `eventN` or the RTC is `rtc0`, edit
`kindle/kiosk.env` accordingly.

## 2. Server side (your Docker host on the same LAN)

```sh
cp .env.example .env
# set HA_URL and your Home Assistant long-lived access token
docker compose up -d
```

This starts the nginx token proxy **and the renderer** (the component
that turns HA state into `dashboard.png` + `dashboard.map` for the
native kiosk). Check from a desktop browser:

- `http://<server-ip>:8124` → browser dashboard
- `http://<server-ip>:8124/generated/dashboard.png` → rendered image
- `http://<server-ip>:8124/generated/dashboard.map` → touch-region map

## 3. Home Assistant side

- Long-lived token in `.env` (`KINDLE_HA_TOKEN`).
- Merge `homeassistant/configuration-snippet.yaml` → `input_boolean.kindle_wake`.
- Merge `homeassistant/automation-presence-wake.yaml`, adapt the
  presence triggers, restart HA.
- Edit `renderer/config.json` to your entities (the renderer loops over
  these; the map is generated from the same layout).

## 4. Kindle side (KUAL-only install)

Set `SERVER_IP` in `kindle/kiosk.env`, then:

```sh
KINDLE_IP=<kindle-ip> KUAL_ONLY=1 bash scripts/install-kindle.sh
```

This pushes everything to `/mnt/us` and **skips the upstart jobs** (they
are not used on this firmware). Nothing is written to the rootfs on the
EY21 — the whole kiosk lives on the userstore and is trivially removed.

For the **native kiosk**, build the touch helper first (needs zig, see
`kindle/native/Makefile`):

```sh
make -C kindle/native
KINDLE_IP=<kindle-ip> KUAL_ONLY=1 bash scripts/install-kindle.sh
```

Then, on the Kindle:

**KUAL → KindleNative → Start Native Kiosk**

That entry stops the Amazon GUI (`lab126_gui`), suppresses the framework
screensaver, and runs the fetch/paint/tap/sleep loop in the foreground.
Stopping is one KUAL tap away (Stop Native Kiosk restores the reader).

## 5. Verify the power story

| Check | Expectation |
|---|---|
| Dashboard renders | Fills 1236×1648, no clipping |
| Tap a toggle region | E-ink repaints within ~1–2s with the new state |
| Leave it idle `IDLE` seconds | Deep sleep (WiFi off; ping stops; image stays) |
| Press power button while suspended | Wakes; Start Native Kiosk via KUAL to resume |
| Turn on `input_boolean.kindle_wake` in HA | Dashboard refresh within ~`POLL` seconds |
| Check `sensor.kindle_battery` in HA | Battery percentage after the first awake cycle |

Battery note: on the PW5, verify what `gasgauge-info -s` prints in your
shell — if the percentage isn't a clean number, adjust the parsing in
the engines and report it back upstream.

## 6. Daily use on the EY21

- After a **reboot** the kiosk does not auto-start — open KUAL and start
  it. Manual start keeps the install rootfs-free.
- `Toggle Sleep Engine` (KindleKiosk menu) keeps it awake while
  charging/debugging.
- **Stop Native Kiosk / Stop Kiosk** returns the stock reader UI.

## 7. Uninstall

```sh
ssh root@<kindle-ip>
rm -rf /mnt/us/kiosk /mnt/us/extensions/KindleKiosk /mnt/us/extensions/KindleNative
rm -f /mnt/us/DISABLE_KIOSK /mnt/us/DISABLE_SLEEP
```

Reboot, and the Kindle is back to stock behavior.

## EY21 troubleshooting

- **`web-reader` app id doesn't open the browser** on your firmware
  (browser mode only): see `docs/MODELS.md` §3 for alternates.
- **Native mode: wrong coordinates on tap** — raw evdev coordinates should
  match framebuffer coordinates on the EY21; if they are swapped or
  scaled, report both a known tap point and the rendered `dashboard.map`
  region and the mapping gets a calibration option.
- **Ghosting bothers you**: the loop repaints on content change; for more
  aggressive cleaning, lower `LIGHT_SLEEP_MAX` so it deep-sleeps sooner.
